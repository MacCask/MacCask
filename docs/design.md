    ├── Platform/                 # 平台接口（协议）

每个业务模块内部再按 `Models / Services / ViewModels / Views` 拆分文件。模块之间只通过 Service 层的公开接口交互，View 不跨模块引用。

## 3. 平台抽象层（Platform）

所有与操作系统交互的调用都通过协议封装，macOS 实现放在 `Platform/macOS/`，将来如需支持其他平台，只需新增对应实现，业务代码不受影响。

| 协议 | 职责 | macOS 实现 |
| --- | --- | --- |
| `CommandRunning` | 执行外部命令，支持流式输出 | `Process` + `Pipe` |
| `PrivilegedCommandRunning` | 以管理员权限执行命令 | `osascript ... with administrator privileges` |
| `FileTrashing` | 把文件移到废纸篓 | `FileManager.trashItem`，无权限时回退到管理员 `mv` |
| `LoginItemManaging` | 读取/添加/移除登录项 | AppleScript（System Events） |
| `SystemIntegrating` | 在访达中显示、打开系统设置、权限检测、磁盘容量 | `NSWorkspace`、`URLResourceValues` |

统一入口：`Platform.current`（`PlatformServices` 结构体），业务层只依赖协议。

## 4. 数据库设计（SwiftData）

数据库文件：`~/Library/Application Support/MacCask/MacCask.store`

### 4.1 AppSizeCacheEntity —— 应用大小缓存
计算 `.app` 大小需要遍历整个包，耗时较长，按「路径 + 修改时间」缓存。

| 字段 | 类型 | 索引 | 说明 |
| --- | --- | --- | --- |
| path | String | 唯一索引 | 应用路径 |
| modifiedAt | Date | | 应用包修改时间，变化则缓存失效 |
| sizeBytes | Int64 | | 占用大小 |
| updatedAt | Date | 索引 | 缓存写入时间 |

查询：`paths.contains($0.path)`，按扫描到的路径批量查询，命中唯一索引。

### 4.2 IgnoredLeftoverEntity —— 已忽略的残留项

| 字段 | 类型 | 索引 | 说明 |
| --- | --- | --- | --- |
| identifier | String | 唯一索引 | 残留项标识（通常是 bundle id） |
| createdAt | Date | 索引 | 忽略时间 |

查询：`ids.contains($0.identifier)`，只查询本次扫描出的标识符。

### 4.3 DisabledLoginItemEntity —— 已关闭的登录项
macOS 没有「禁用登录项」的公开接口，关闭即从登录项中移除；为了能再次开启，需记录被关闭的登录项。

| 字段 | 类型 | 索引 | 说明 |
| --- | --- | --- | --- |
| path | String | 唯一索引 | 登录项应用路径 |
| name | String | | 显示名称 |
| disabledAt | Date | 索引 | 关闭时间 |

查询：按 `disabledAt` 排序读取全部记录（业务语义上就是「所有被关闭的登录项」，符合「条件过滤出来是全表」的例外）；删除时按 `path` 唯一索引定位。

## 5. 功能模块设计

### 5.0 概览（Overview）
启动后的默认页面，整页仪表盘（两栏布局：侧边栏 + 仪表盘），汇总其他模块的数据。

- **磁盘占用**：启动磁盘的已用百分比（大号数字），分段条按占整个磁盘的比例展示
  第三方应用（程序包及关联数据，共享路径去重）/ Homebrew（Cellar + Caskroom）/ 用户缓存（扣除已归入应用的部分）/ 残留文件（排除缓存及应用已归属部分）/ 其他已用 / 可用；
  图例逐项列出大小与占磁盘百分比，悬停高亮对应分段，点击跳转到对应模块。剩余空间低于 20% / 10% 时显示警告标签。
- **状态磁贴**：应用程序、Homebrew（含可更新数）、启动项（已开启 / 运行中）、残留文件（可清理大小），点击跳转。
- **占用最多的应用**：前 8 个第三方应用的横向条形列表，按程序包与关联数据的总占用排序，显示大小与占磁盘比例，悬停高亮，点击跳到该应用详情。读取不完整时保留“至少”标识。
- **应用来源**：环形图（第三方 / Homebrew / App Store / 系统），悬停时中心显示该来源数量。
- **使用活跃度**：按上次使用时间分组（7 天内、30 天内、半年内、一年内、超过一年、未知）的柱状图，悬停显示该组合计大小；标题右侧显示超过一年未使用应用的占用。
- **建议**：磁盘空间不足、Homebrew 可更新、残留可清理、长期未使用的应用、守护进程过多等，按严重程度排序，点击跳转处理。
- **配色**：分类色按固定顺序（蓝、橙、青、黄），浅色/深色模式各自取值，已通过色盲区分度校验；「其他」与「未知」使用中性灰；状态色（警告/严重）只用于建议与警告标签，并始终配合图标与文字。
- 磁盘分段与来源环形图中，同一实体颜色一致（如 Homebrew 始终为橙色）。
- **联动**：首页与应用列表共享 `InstalledAppsViewModel.totalSizes` 和对应文件明细，不再使用包大小缓存生成首页占用。刷新、详情重新分析、卸载立即影响排行、总量、活跃度及建议；占用批次完成后或返回首页时，合并短时间内的变化并补充读取磁盘、Homebrew、用户缓存。取消旧任务可避免较早结果覆盖新统计。磁盘分类对重复/父子路径去重，关联缓存只计一次；共享数据按应用展示各自关联占用，磁盘分段按唯一文件计量。

### 5.1 已安装应用（InstalledApps）
- **扫描范围**：`/Applications`（含一级子目录，如 Utilities）、`~/Applications`、`/System/Applications`（含 Utilities）。
- **应用信息**：名称、Bundle ID、版本、图标、上次使用时间（Spotlight `kMDItemLastUsedDate`）。
- **标签**：
  - `系统`：位于 `/System/` 下，或 Bundle ID 为 `com.apple.*` 且非 App Store 安装 —— 系统应用禁止卸载；
  - `App Store`：包内存在 `Contents/_MASReceipt`；
  - `Homebrew`：与 Homebrew Cask 的 `app` artifact 匹配。
- **大小**：应用列表、大小排序和列表合计使用“应用包 + 关联数据”；详情仍分列应用包大小与关联数据。`AppUsageScanner` 持有共享结果、失效版本及在途任务，列表与详情合计最多同时分析四个应用；已有结果直接复用，未扫描的应用显示“计算中…”。更新期间保留旧数值并显示轻量进度，读取不完整显示容量下限或“无法读取”。包大小数据库缓存仅用于提前展示详情，完整结果和顶层文件明细保存在内存，不保存每个内部文件的清单。首页读取同一份统计，磁盘分类按文件明细去重。
- **目录变化与更新策略**：业务通过 `FileChangeMonitoring` 接口接收目录变化，macOS 使用一条 FSEvents 事件流，目录级通知合并延迟 3 秒，不订阅逐文件事件。监听应用安装目录及相关 Library 目录，缺失 Library 子目录监听父目录以发现新数据；真实路径映射回原始路径，排除自身数据库以防反馈循环。已有路径按归属匹配，新关联路径沿用 Bundle ID/名称规则；父目录合并事件保守失效其涉及应用，事件丢失或监听根路径变化时全部失效并重新发现。回调只标记失效，前台合并更新，自动扫描轮次至少间隔 30 秒，后台不启动自动扫描。回到前台重新发现安装信息，监听正常时对超过 24 小时的结果进行兜底核验；监听启动失败时缩短到 5 分钟并重试监听；用户刷新仍强制失效全部应用。
- **任务复用与取消**：页面切换及 A/B/A 选中切换不重新统计已有有效结果；列表和详情共享同一个在途分析。扫描期间的新变化保留失效标记，等待过期任务的请求只补扫一次。离开详情仅取消页面等待，共享扫描仍发布到列表和首页；应用移除才取消其共享任务，并将取消传递给后台遍历。所有结果写回都检查应用仍存在，更新详情时保留用户勾选，新出现文件不自动勾选。
- **关联文件分析**：在 `~/Library` 与 `/Library` 的常见目录（Application Support、Caches、Preferences、Containers、Group Containers、Saved Application State、Logs、HTTPStorages、WebKit、Cookies、LaunchAgents、LaunchDaemons、PrivilegedHelperTools）中，按 Bundle ID / 应用名匹配，列出每个路径及其大小。
- **统计完整性**：关联分析保留根目录枚举、子目录遍历和文件属性读取失败的路径；未创建的 Library 根目录不算错误。部分结果显示“至少 …”，完全未读到数据时显示“无法读取”，详情列出失败路径并提供完全磁盘访问权限设置入口。授权后重启应用，现有刷新操作同步重新分析关联数据。不跟随符号链接，包含隐藏文件和包内文件；不通过厂商级模糊匹配扩大删除范围。
- **卸载**：勾选需要删除的关联文件，确认后统一移到废纸篓（可恢复）；Homebrew 安装的应用改为调用 `brew uninstall --cask`；应用运行中时阻止卸载并提示。
- **列表交互**：搜索、分类筛选（全部/第三方/系统/App Store/Homebrew）、排序（名称/大小/上次使用）。

### 5.2 Homebrew（Homebrew）
- 通过 `brew info --json=v2 --installed` 一次获取所有 Formula 与 Cask 的安装版本、最新版本、是否过期、描述、主页。
- 分段切换 Formula / Cask，可筛选「仅显示可更新」。
- 详情：版本对比、是否主动安装（区分依赖）、安装目录与占用大小、主页链接。
- 操作：升级单个、全部升级、卸载、更新 Homebrew 源（`brew update`）。
- 所有命令通过流式日志面板展示实时输出，执行完毕后自动刷新列表。
- 未安装 Homebrew 时显示空状态与安装指引。

### 5.3 开机启动项（LaunchItems）
- **登录项**：通过 System Events 读取；关闭 = 移除并写入 `DisabledLoginItemEntity`，开启 = 重新添加并删除记录。
- **用户代理**：`~/Library/LaunchAgents`；**全局代理**：`/Library/LaunchAgents`；
  开关使用 `launchctl disable/enable gui/<uid>/<label>` 并 `bootout/bootstrap`。
- **系统守护进程**：`/Library/LaunchDaemons`，开关需要管理员权限（`system/<label>` 域）。
- 启用状态 = `launchctl print-disabled` 覆盖值优先，其次 plist 的 `Disabled` 键。
- 运行状态来自 `launchctl list`。
- 详情展示 Label、执行程序、参数、RunAtLoad、KeepAlive、plist 路径；可在访达中显示。
- 提供「打开系统登录项设置」入口，管理 macOS 13+ 的后台项目（SMAppService）。
- 苹果自身（`com.apple.*`）的启动项不展示，避免误操作。

### 5.4 残留文件（Leftovers）
- 扫描与关联文件分析相同的 Library 目录，从文件名中提取标识符（去掉 `.plist`/`.savedState`/`.binarycookies` 后缀、ByHost 的 UUID 后缀、Group Container 的 `group.` / TeamID 前缀）。
- 只处理反向域名格式的标识符（如 `com.vendor.app`），降低误报。
- 已安装集合 = 扫描到的应用 + Spotlight 全盘 `.app` 索引（含辅助程序）+ 正在运行的应用。
- 判定：标识符不以 `com.apple.` 等系统前缀开头，且与任何已安装 Bundle ID 不相等、不互为前缀，即为残留。
- 可信度：同厂商（前两段相同）仍有应用安装的，标记为「低可信度」。
- 按标识符分组，展示总大小、位置；支持多选移到废纸篓、忽略（持久化）、显示已忽略。
- 未授予「完全磁盘访问权限」时显示提示条，引导打开系统设置。

## 6. UI 设计

- 主窗口 `NavigationSplitView` 三栏：侧边栏（模块）→ 内容列（列表）→ 详情列。
- 侧边栏显示每个模块的数量徽标：应用程序为第三方应用数，Homebrew 为可更新数，启动项为已开启数，残留文件为未忽略的残留数。
- 工具栏只放与当前模块相关的主要操作：刷新、批量操作；破坏性操作必须二次确认。
- 次要操作放入右键菜单（在访达中显示、拷贝路径、忽略等），不额外增加按钮。
- 统一的标签组件（系统/App Store/Homebrew/可更新/低可信度），颜色语义一致。
- 长耗时任务显示进度；命令类任务显示实时日志面板。
- 支持浅色/深色模式（使用系统语义色）。

### 6.1 语言与设置

- 新增 `Localization/Models/AppLanguage.swift` 与 `Localization/Views/LanguageSettingsView.swift`，使用 macOS 标准 Settings 场景和 `⌘,`，应用菜单只保留系统自动生成的带图标设置入口，不额外添加 SettingsLink，也不向业务页面增加语言按钮。
- 默认偏好为 `system`，按 `Locale.preferredLanguages` 顺序匹配英语或简体中文；未匹配时回退到英语。显式偏好使用稳定值 `en` / `zh-Hans`，通过 `UserDefaults` 保存。
- `Utils/L10n.swift` 统一翻译与插值，中文原文作为资源键，英语译文在 SwiftPM 资源 `App/Resources/English.json` 中。占位符采用 `{0}`、`{1}`，单次替换，不将动态应用名、路径或命令输出作为翻译键。
- 应用入口观察语言偏好，立即重建展示视图并注入所选 locale；全局 `AppState` 保留，模块数据、选中项与执行中的命令不重新创建。菜单栏和设置界面同步更新。
- 侧边栏、筛选、详情、仪表盘、弹窗、工具提示及应用生成的错误文案接入翻译；日期、容量与百分比使用所选 locale。应用名称、Bundle ID、路径、包描述和命令输出保留原文。
- 枚举原始值与展示标题分开处理，`AppFilter`、`LaunchItemSource`、`LibraryCategory` 等既有标识不变，避免影响选择和持久化记录。
- 应用包声明 `en` 与 `zh-Hans`，打包时复制两种语言的 `InfoPlist.strings`，供系统授权弹窗使用；系统授权界面的语言由 macOS 决定。
- 仪表盘磁贴的说明与状态标签分行，允许较长的英文说明换行，保持各磁贴等高。

## 7. 打包

### 版本与 GitHub Release

- 根目录 `VERSION` 是唯一版本来源，初始 `1.0.0`，统一使用 `Scripts/Utils/read-version.sh` 校验数字三段版本；Makefile 不接受命令行版本覆盖。`ARCH` 明确指定 `x86_64` 或 `arm64`，编译和定位 SwiftPM 产物使用同一架构参数。
- `make release` 先完成原有应用打包，再由 `Scripts/Release/package-app.sh` 验证版本、单一架构及签名，用 `ditto` 保留应用签名及资源，再由 `hdiutil` 生成压缩只读 HFS+ 映像 `build/releases/MacCask-<版本>-macos-<架构>.dmg`，包含应用和 Applications 安装快捷方式，并验证映像完整性。
- `.github/workflows/release.yml` 由 tag 推送触发，先校验 tag 与 VERSION 相同（允许可选 `v` 前缀），检查签名 Secrets，再使用 Xcode 26.6 和两个 `macos-26` ARM runner，分别交叉编译 x86_64 和原生构建 arm64；图形与业务完整测试在原生 arm64 作业运行。Intel 虚拟机的 Metal 驱动会导致渲染测试崩溃或卡住，因此不作为图形测试宿主。
- 签名仅需要 `BUILD_CERTIFICATE_BASE64` 和 `P12_PASSWORD` 两个 Secrets，签名身份由导入的 p12 自动识别。临时钥匙串密码由 runner 自行生成，`Scripts/Release/import-certificate.sh` 导入身份后用 `Scripts/Utils/select-signing-identity.sh` 选择唯一的代码签名私钥身份，按指纹匹配公开证书并建立自签证书信任，签名使用确切指纹；缺少私钥或 Secrets 则失败，不以 ad-hoc 签名发布。
- 两个架构成功后，独立发布任务通过 GitHub 自动 Token 创建草稿 Release，上传两个 DMG 和 `SHA256SUMS`，全部上传成功后清理当前版本遗留的 Intel/ARM ZIP 附件，再公开。重跑支持覆盖同名附件。只有发布任务拥有 `contents: write`，构建任务结束始终清理临时签名材料。
- 当前签名身份为本机自签证书，不执行 Apple 公证；Release 说明明确这一状态。配置与导出步骤放在 `docs/releasing.md` 和 `docs/releasing.zh-CN.md`，README 只提供简短链接。

- `make build`：Release 编译
- `make app`：生成 `build/MacCask.app`，写入 Info.plist、图标，并用系统中现有的自签证书签名
- `make run`：打包并启动
- `make install`：复制到 `/Applications`
- `make clean`：清理

## 8. 应用图标设计（已选 H「折叠」）

- 用户已选定第三轮第一个方案 H：紫色顶折面、钴蓝侧面、青色下折面形成开放的 C。按最新反馈，源图改为平面、满版方形，移除预制圆角底板、阴影与立体材质。
- 正式图标源为 `Resources/AppIcon.icon`：`icon.json` 定义背景、外观和材质，`Assets/` 中三个无圆角、无阴影的 SVG 色面共同构成折叠 C。`Resources/AppIcon/master.png` 与 `AppIcon-1024.png` 保留为选定平面方案参考。
- `Scripts/build-icon.sh` 调用 Xcode 26 的 `actool`，由系统编译器生成 `Assets.car` 和兼容 ICNS；`make app` 将它们嵌入应用，并合并编译器生成的 `CFBundleIconName` / `CFBundleIconFile` 后签名。圆角和材质由苹果图标渲染器处理，不画进源图。
- 编译目标最低 macOS 15：新系统读取分层资源，旧系统读取编译器输出的兼容 ICNS。`Resources/AppIcon/Previews/` 保存苹果 `ictool` 输出的默认、深色、浅/深着色、浅/深透明六种外观预览。
- `swift run` 从 SwiftPM 资源包读取预生成 ICNS，通过 `SystemIntegrating.setApplicationIcon` 的 macOS 实现设置 Dock 图标；不依赖当前工作目录。正式 `.app` 不执行这一步，避免覆盖系统动态外观。修改 `.icon` 后运行 `make icon` 同步开发资源，`make app` 自动执行。
- 菜单栏/托盘图标独立于 Dock：`Resources/MenuBar/MenuBarTemplate.svg` 为单色折叠 C 轮廓，`MenuBarTemplate.pdf` 为 18pt 矢量模板，另有 18/36 像素 PNG 和深浅背景预览。通过 `Scripts/make-menubar-icon.swift` 统一生成，不包含底板、圆角或阴影。
- `MenuBar/MenuBarMenu.swift` 使用 `MenuBarExtra` 显示模板图标，系统按背景与选中状态着色。菜单只提供“打开 MacCask”和“退出 MacCask”；打开动作复用主窗口并恢复最小化状态。
- 默认显示菜单栏图标，支持在“视图切换 → 显示菜单栏图标”中隐藏并保存偏好。开启时关闭主窗口仍运行，可从菜单栏重新打开；隐藏时关闭最后一个窗口即退出。
- 打包时复制 SwiftPM 资源包到应用的 `Contents/Resources`，`AppResources` 统一定位资源；菜单栏图标在正式应用和 `swift run` 下使用相同的 PDF，不依赖开发目录。

### 方案探索记录

### 启动响应与原生菜单语言

- 关联文件扫描由独立 utility 任务执行，扫描器仅在主执行器协调状态；读取应用修改时间和磁盘容量也在后台完成。缓存与 Homebrew 容量任务将取消传递到文件遍历，防止过期任务继续竞争磁盘。
- 概览磁盘分类使用路径祖先索引，避免对每一对 URL 重复标准化和比较。分类以不可变输入快照在后台合并计算，取消的旧结果不发布；SwiftUI 绘制读取已有分类结果，悬停和窗口尺寸变化不触发目录计算。文件通知同样预处理路径以减轻主线程路由工作。
- macOS 自动生成的菜单不继承页面的 SwiftUI locale。通过系统集成接口，在启动、偏好变化及菜单打开时同步原生菜单标题；使用系统动作识别关于、隐藏、退出等项，设置保留系统提供的图标、快捷键及响应链。服务提供者的子菜单由 macOS 管理，不修改第三方命令。

### 列表操作层级

- 采用最终选定的侧栏分类方案：应用程序可展开全部应用、第三方应用、系统应用、App Store 与 Homebrew 安装，各分类显示实际数量并直接切换应用列表。展开状态持久化；切回应用模块自动展开以显示选中分类。
- 搜索保留窗口顶部，列表头仅显示当前分类标题、数量和排序菜单。详情的版本、包大小、关联数据与上次使用采用平面统计栏与细分隔线。
- 概览、应用程序、Homebrew、启动项及残留文件的刷新操作位于各自一级行的右键菜单，行内仅显示名称与数量。应用二级分类不提供右键刷新，左键筛选保持可用。按右键所在模块刷新，不切换页面；概览沿用刷新全部数据的语义。刷新中菜单显示“正在刷新…”并禁用重复触发。全局 Command-R 继续刷新当前页面。
- 侧栏底部仅保留废纸篓说明；导航、列表头和侧栏底部独立为组件，中英文演示直接复用原生组件。

### GitHub 应用内更新

- macOS 通过 Sparkle 2.10 接入更新，平台接口位于 `Platform/AppUpdating.swift`，界面提供应用菜单“检查更新…”与标准设置中的自动检查开关，默认不自动检查或静默安装。
- 更新直接复用 Intel/ARM DMG，每个架构读取 GitHub 最新 Release 上独立的签名 appcast；Action 生成、验证并随 DMG 上传，无需独立服务器或 GitHub Pages。
- Ed25519 公钥嵌入应用，私钥仅保存在钥匙串、本机忽略目录及 GitHub Secret。解包前验证归档，并验证清单；自签应用身份保持不变，框架和助手由内到外签名。
- 正式版本与内部构建号统一取 VERSION，避免本地时间戳与 CI 序号混用导致无法识别更新。旧版需要手动安装首个包含更新器的版本。
- 更新代码不会在裸可执行文件或文档画布启动；发布包仍需验证真实的下载、退出、替换和重启流程，自签更新不宣称获得 Apple 公证。

### 页面内更新提醒

- 启用自动检查后，后台发现新版本仅在主窗口顶部显示跨模块提示条，包含版本号与“查看更新…”入口，不抢焦点、不自动下载。没有更新时不占据空间。
- 用户点击提示后才打开 Sparkle 标准更新窗口，由用户决定下载及安装时间；取消、跳过或更新会话失败后清除提示。手动“检查更新…”仍提供即时窗口反馈。
- 使用 Sparkle Gentle Reminders 委托保留官方会话和签名验证流程；打包明确关闭自动下载安装能力。文档渲染提供虚构更新提示预览，不访问更新源。

### 自动更新集成验证

- `Tests/Release/run-update-integration.py` 创建唯一测试 Bundle ID、回环 HTTP 服务和两个已签名应用版本。测试入口复制正式更新器，仅增加立即后台检查入口；复用正式页面提示及 Sparkle 标准用户界面，在测试进程内模拟点击。
- 安装场景校验后台阶段未请求 DMG、没有弹窗，主动安装后旧版被替换且新版真实启动，最后重新验证应用签名。取消场景通过关闭更新窗口实现稍后提醒，校验无 DMG 请求、版本未变、提示清除。
- 证据与模拟应用保存在 build/update-integration-*，不修改 /Applications/MacCask.app 或正式偏好，不使用真实业务数据，不发布测试 Release。

- 当前外观跟随 macOS 系统设置，没有应用内独立切换入口；中英文 README 明确注明跟随系统。

### 侧栏外观切换

- 侧栏底部右侧固定单击外观切换按钮，与左侧文件恢复说明并排。默认跟随系统；首次点击根据当前实际外观切换至相反模式，之后保存用户选择，不再跟随系统。浅色时显示月亮，深色时显示太阳，表示点击后的目标外观，不弹出菜单。
- 外观由平台系统集成接口作用于整个应用，保证主窗口、设置及 Sparkle 更新窗口一致；尚无用户选择时保持系统外观。截图渲染使用临时状态，不读取真实外观偏好。

### App Store 版本查询

- 仅为识别为 App Store 来源的应用在详情版本统计下增加商店版本状态，按 Bundle ID 精确匹配 mac-software，不按名称猜测。使用系统地区（无地区时 US），界面显示查询地区，不读取 Apple 账户信息。
- 公共 lookup 请求在独立 actor 中限速（至少 3.1 秒间隔），按 Bundle ID 和地区缓存五分钟并合并进行中请求，不阻塞本地扫描。切换应用后不发布旧任务结果；失败可重试，空结果显示当前地区未找到。
- 仅纯数字分段版本明确更高且满足最低系统要求时显示“在 App Store 中更新”，其他已匹配项提供查看入口。由系统 App Store 完成账户验证和安装，MacCask 不直接下载或替换商店应用。
- 查询结果受商店地区及目录同步延迟影响，不等同于已登录账户的更新列表；系统要求高于当前版本时明确展示要求。

- 商店版本支持右键“重新查询商店版本”绕过内存缓存，并禁用 URLSession 本地响应缓存；真实网络请求添加独立缓存标识及 no-cache 请求头，避免复用旧目录响应。Apple 服务端的目录延迟仍可能存在。

### App Store 列表更新标记

- 打开应用列表后，独立任务顺序查询已安装的 App Store 应用，无需逐个选择详情；复用缓存与请求限速，切换分类不按行重复发请求，离开页面后停止安排新查询。
- 应用名称旁使用与 Homebrew 相同的“可更新”标签，悬停显示商店版本。只标记明确更新且系统兼容的商店应用；本地版本升级后比较当前安装信息，标记自动消失。
- 列表与详情共用可观察商店结果，详情强制重新查询会更新列表；查询失败、未找到或非标准版本不误报可更新。
